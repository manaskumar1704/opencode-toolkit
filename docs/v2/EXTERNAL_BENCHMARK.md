# External Benchmark — Terminal-Bench 2.0

**Status:** selected 2026-11-11 (R-3). Not yet executed.
**Code:** `benchmarks/external.py` · **Tests:** `tests/test_external.py`
**Handoff:** D8 (pick one), D2 (fixed configuration), D7 (integrity)

---

## 1. Decision

**Terminal-Bench 2.0, run through Harbor**, dataset
`terminal-bench/terminal-bench-2` (89 containerised tasks).

Chosen over SWE-bench Lite because:

| Criterion | Terminal-Bench 2.0 | SWE-bench Lite |
|---|---|---|
| Outcome-based verification | Yes — tests run against container state | Yes — repo tests |
| Task diversity | Terminal work across domains | Python repo patches only |
| Agent-agnostic harness | Harbor ships an OpenCode agent | Requires a patch-extraction adapter |
| Verification quality | Rebuilt and re-verified for 2.0 | Older, known contamination |
| Cost to start | Docker + `uv tool install harbor` | Docker + dataset tooling |

The point is not a leaderboard number. It is one question: **does the OCTK
effect survive contact with tasks we did not write?**

## 2. Scope

The external benchmark runs **two arms only**:

| Arm | OCTK | Everything else |
|---|:--:|---|
| A | off | same harness, model, effort |
| E | on | same harness, model, effort |

The eight-arm Ponytail/Graphify factorial stays internal. Mixing the two would
confound "does OCTK generalise" with "do the optional providers interact",
which is a different question and a much larger bill.

## 3. Cohort lock

`ExternalCohort.validate()` refuses to build a command if any of these drift:

| Field | Locked value |
|---|---|
| Dataset | `terminal-bench/terminal-bench-2` (alias `terminal-bench@2.0`) |
| Agent | `opencode` (Harbor built-in) |
| Model | `opencode-go/beam-free` |
| Effort | `high` |
| Attempts | ≥ 5 per task (pass@k reporting) |
| Concurrency | ≥ 1 |

Probe cohorts (`attempts=1, probe=True`) are allowed for the feasibility ladder
only. `preregistration()` refuses to record a probe as evidence.

## 4. Feasibility ladder

Run these in order. Each rung must pass before spending on the next.

| # | Rung | Passes when |
|---|---|---|
| 1 | Oracle on 5 tasks | reference solutions score 1.0 |
| 2 | One task, OpenCode, no OCTK | agent completes; verifier writes a reward |
| 3 | One task, OpenCode, OCTK mounted | agent starts; OCTK MCP tools appear in logs |
| 4 | Five-task pilot, both arms | all runs complete; no unclassified provider errors |
| 5 | Full 89-task run, both arms | pre-registration recorded; correctness compared first |

Commands are generated by `benchmarks.external.smoke_ladder()` so they cannot
drift from the lock. Rung 1:

```bash
harbor run -d terminal-bench@2.0 -a oracle -n 4 -k 5 \
  --jobs-dir benchmarks/results/external -l 5
```

## 5. The adapter gap (must be closed before rung 3)

Harbor's built-in `opencode` agent runs OpenCode inside the task container, but
it does **not** install OCTK. Rung 3 needs a thin custom agent that:

1. installs OpenCode (same as the built-in agent);
2. installs OCTK in the image — `pip install opencode-toolkit` (or a pinned
   wheel for reproducibility);
3. writes the OpenCode config with the `octk` MCP server (arm E only). The
   config content is generated by `octk_config_content()` and passed as
   `--ae OPENCODE_CONFIG_CONTENT=...`;
4. runs `opencode run --format json` and records the JSONL transcript.

This is a packaging adapter, not a reimplementation of OCTK. It lives outside
`octk/` and must not leak harness assumptions into the core (handoff B1).

## 6. Pre-registration

Write `benchmarks/results/external/preregistration.json` **before** rung 4.
`preregistration()` emits the fields. Two are intentionally unfilled until the
smoke test proves them:

- `dataset_version_hash` — hash of the downloaded dataset;
- `credential_env_var` — the environment variable that authenticates the
  `opencode-go` provider inside the container.

If either cannot be pinned, the run does not start.

## 7. Cost honesty

- Stage 1 of the internal benchmark must finish first; its measured mean is the
  only defensible basis for an external cost estimate.
- Until then, external cost is `UNKNOWN`.
- The five-task pilot is the first real measurement. Record it, then extrapolate
  explicitly and label the extrapolation.
- Published numbers must separate correctness from efficiency. Correctness is
  the gate.

## 8. Abort and relabel rules

| Event | Action |
|---|---|
| `beam-free` disappears or is renamed | Abort, relabel the cohort, restart (handoff Q10) |
| Dataset version changes mid-run | Abort; hashes will not match |
| Provider errors > 10% of runs | Stop; the comparison is not valid |
| Any OCTK correctness regression | Stop; fix before spending on the rest |
| Docker runs under emulation | Do not publish rewards |

## 9. Acceptance criteria

An external result may be reported only when all of these hold:

- [ ] Pre-registration recorded before the run.
- [ ] All 89 tasks attempted, 5 attempts each, both arms.
- [ ] Dataset hash and OpenCode version recorded.
- [ ] Correctness compared first, per task, with confidence intervals.
- [ ] Efficiency reported as gross and net, separately.
- [ ] Provider errors and rate limits logged, not hidden.
- [ ] The adapter source is committed and reviewable.
