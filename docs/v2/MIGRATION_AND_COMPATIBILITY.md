# OCTK v2 — Migration and Compatibility

## Who this is for

Existing OCTK users upgrading from v1 to v2. If you are installing fresh, skip
this document.

## What changes, what doesn't

### Unchanged (your work is safe)

| Item | Location | Status |
|---|---|---|
| `.toolkit/specs/*` | project | unchanged |
| `.toolkit/skills/*` | project | unchanged |
| `.toolkit/index.md` | project | unchanged |
| `.toolkit/config.json` | project | deep-merged with new defaults; your keys win |
| `.toolkit/metrics.json` | project | unchanged format |
| `.toolkit/approvals.json` | project | unchanged |
| `.toolkit/roadmap.md` | project | unchanged |
| `.toolkit/handoff.md` | project | unchanged |
| `AGENTS.md` | project | sentinel-preserved; user text outside sentinels kept |
| `opencode.json` | project | merged, not overwritten |
| Git history | project | untouched |

### Changed (new in v2)

| Item | What happens |
|---|---|
| `.toolkit/capabilities/index.json` | **new** — created by `octk capabilities discover --write`. Not present until you run it. |
| `.toolkit/capabilities/local.json` | **new** — machine-local, gitignored |
| MCP tool count | 10 → 8. `run_audit_workflow` and `update_roadmap` are now CLI-only. |
| Agent scaffolding | unchanged files, but generated by the adapter now |
| Python floor | 3.14 → 3.11 (broader adoption) |

### Removed from core (dropped)

| Item | Replacement |
|---|---|
| `octk models` / `set-model` / `set-effort` | Use your harness's own model configuration. These commands still work but print a deprecation warning. |
| Mandatory plan/build/explore/verifier subagents | Not required; use your harness's native agents. |
| Multi-model quota routing | Not supported. |

## Upgrade steps

1. **Back up your project** (git commit or archive). OCTK never mutates user config, but backups are cheap.

2. **Update OCTK:**
   ```bash
   uv sync  # or your install method
   ```

3. **Verify your tests still pass:**
   ```bash
   uv run pytest -q -m "not browser"
   ```

4. **Regenerate the capability index (optional but recommended):**
   ```bash
   octk capabilities discover --write
   octk capabilities verify
   ```

5. **Check the audit still works:**
   ```bash
   octk audit
   octk doctor
   ```

6. **Update any agent prompts** that reference `update_roadmap` or `run_audit_workflow` as MCP tools. These are now CLI commands:
   ```bash
   octk roadmap set "<task>" done   # replaces update_roadmap(task, "done")
   octk audit                      # replaces run_audit_workflow()
   ```

## MCP surface change (breaking)

Two tools were removed from the MCP server:

| Removed tool | CLI replacement | Why |
|---|---|---|
| `update_roadmap` | `octk roadmap set` | Consequential action; approval gate lives in the CLI |
| `run_audit_workflow` | `octk audit` | Workflow orchestration, not a per-turn agent need |

If your agent prompts or skills call these as MCP tools, update them to use the CLI. The `octk approve "<task>"` flow is unchanged.

## Python version

v2 lowers the minimum Python version from 3.14 to 3.11. If you were running 3.14, nothing changes for you. If you were blocked on 3.14, you can now use 3.11+.

## External providers

Ponytail and Graphify remain external. OCTK v2 detects them but never installs, updates, or bundles them. If you had them configured in v1, they continue to work unchanged.

## Rollback

If v2 causes problems:

1. `git checkout` your pre-upgrade commit (or restore from backup).
2. Reinstall the previous OCTK version.
3. Your `.toolkit/` state files are forward-compatible — v1 will ignore `.toolkit/capabilities/` without error.

## What to report

If you hit an issue during migration, report:
- OCTK version before and after
- Python version
- OpenCode version
- The exact error and the command that produced it
- Whether `.toolkit/capabilities/index.json` exists
